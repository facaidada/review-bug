# 修复已确认问题提示词

只在 Owner 已确认具体问题并授权修改后使用。

```text
请先读取【review-bug 绝对路径】/docs/review-framework-v1.md，再修复问题【F-编号和标题】。

授权范围：【允许修改的文件或模块】
禁止范围：【不能碰的目录、数据、账号、生产环境】
验收条件：【AC 编号和预期结果】

要求：
1. 先核对基线、分支、commit、Git dirty 状态和未跟踪文件，保留用户已有改动；不要 reset、clean 或覆盖它们。
2. 先保留修复前失败证据，再做最小修复。一次只修这个确认问题，不顺手重构、升级依赖或修改验收条件。
3. 保持单一 Writer。Reviewer 和 Verifier 不参与实现。
4. 依次执行：修复前失败、聚焦回归、正确结果对照、相关全量测试，以及适用的 type/lint/build/扫描。
5. 测试桩只能证明对应测试，不能写成真实浏览器、网络、数据库或生产通过。
6. 不安装新工具、不联网、不付费、不登录、不提交、不推送、不发布，除非本任务分别明确授权。
7. 不在输出、日志、截图或提交中显示任何秘密。
8. 交付完整差异、验证命令与结果、未覆盖层、回滚对象，并把状态停在 fixed_unverified，等待独立复查。
```
