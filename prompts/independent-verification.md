# 独立验收提示词

建议在 Reviewer 完成后，再用一个新的 AI 任务或独立人员执行。

```text
你是本次任务的独立 Verifier。请先读取【review-bug 绝对路径】/docs/review-framework-v1.md，再验收【已检出的候选分支或 commit】。

输入：
- 任务合同：【路径】
- 问题账本：【路径】
- 基线：【commit】
- 可运行候选：【已检出的分支或 commit】
- 运行环境与启动方式：【路径或命令】
- 验收条件：【AC 列表】
- Reviewer 结论：【路径】

要求：
1. 只读，不修改实现、测试或验收条件；不提交、不推送、不发布。
2. 以任务合同和 AC 验收条件为准，不读取实现来反推“应该怎样才算正确”。
3. 按合同独立运行合法且已授权的黑盒或真实路径验证；不要复用 Writer 的结论代替执行。如果只有 diff、没有可运行候选或环境，相关验收写 blocked，不要假装已执行。
4. 对每个 AC 分别写 pass / fail / blocked / not-testable，并附操作、实际结果和证据。
5. 缺依赖、权限、环境或真实角色时明确写 blocked 或 not-testable，不要猜测为通过。
6. 分开给出自动测试、差异对照、浏览器/角色、实际运行环境、生产和人工业务层的结论，不能相互代替。本来不属于合同范围的层写 not-applicable；本应判断但当前无法完成时写 blocked 或 not-testable，并说明原因。
7. 如果验收中发现新问题，只记录到问题账本，不修改实现；交回单一 Writer 处理。
8. 不显示任何密码、令牌、Cookie、私钥、完整连接串或不必要的个人数据。
9. 最终输出：AC 逐项结果、总体 PASS/FAIL/BLOCKED/NOT_TESTABLE、未决风险和是否可以交给 Owner 决定接受。
```
