## 1. 冻结现场

- 基线 commit / Git dirty 状态：
- 已跟踪修改和未跟踪文件：
- 环境和版本：
- 失败时间、请求或任务 ID：
- 原始日志、截图、输入、输出路径与哈希：
- 已知正确结果：
- 明确禁止的写操作：

- 最小复现步骤：
- 预期：

## 5. 根因与修复门

- 已确认根因：

## 6. 验证

- 修复前失败：
- 聚焦回归：
- 差异或正确结果对照：
- 相关全量测试：
- type / lint / build / 扫描：
- 冷上下文 Review：
- 黑盒或真实角色：
- 没有覆盖的验收层：

注意：测试桩、模拟数据和假账号只能证明对应测试，不能被写成真实运行环境通过。
